# НГУ · облік особового складу / учёт личного состава

Отдельный проект для административного учёта военнослужащих Национальной гвардии Украины. Гражданская версия и OmniFactory CRM не изменяются.

## Нормативная основа

- [Закон України «Про Національну гвардію України» № 876-VII](https://zakon.rada.gov.ua/laws/show/876-18).
- [Наказ МВС № 73 від 30.01.2017: Інструкція з організації обліку особового складу НГУ](https://zakon.rada.gov.ua/laws/show/z0248-17). Основной акт для реестра и печатных форм.
- [Закон України «Про військовий обов'язок і військову службу» № 2232-XII](https://zakon.rada.gov.ua/laws/show/2232-12).
- [Закон України «Про захист персональних даних» № 2297-VI](https://zakon.rada.gov.ua/laws/show/2297-17).

Точную действующую редакцию, приложения и реквизиты каждой официальной формы необходимо проверить перед публикацией формы. Русский язык используется только для интерфейса и внутренних черновиков, официальный украинский текст не переводится.

## Статус

Локальная ветка `feature/ngu-personnel`. Реализован демонстрационный интерфейс на вымышленных записях; программа для реальных персональных данных не выпущена. Запись через подключение GitHub была отклонена (403), поэтому ветку нужно отправить с компьютера пользователя.

## Первый релиз

Сейчас доступны карточка личного состава, история кадровых событий, черновики и согласование периодов отсутствия, журнал административных нарядов, справочник номерного имущества, выдача и возврат, фильтры, обзор и внутренние печатные реестры. Разграничение прав, аудит, интеграции и официальные бланки пока не реализованы. Официальные бланки подключаются по одному после сверки конкретных приложений приказа № 73.

В v0.3 добавлены иерархия подразделений, штатные единицы, занятость/вакансии, назначения по зарегистрированному приказу и демонстрационная цепочка состояний документа. Интерфейс сделан плотнее и строже. Штат и документальные основания остаются синтетическими (`DEMO-...`). См. `docs/ngu_hrm_scope_v0_3.md`.

В v0.4 добавлен `/management`: компактная управленческая сводка по подразделениям, состоянию документов и согласованным отсутствиям, печать и CSV. Это **не официальная строевая записка**. См. `docs/management_v0_4.md` и `UPDATE_v0_4_POWERSHELL.md`.

Не включены сведения о боевых задачах, маршрутах и точном местонахождении личного состава.

## Запуск прототипа в PowerShell (отдельная папка)

```powershell
cd C:\Users\bonda\PycharmProjects
Expand-Archive "$env:USERPROFILE\Downloads\NGU_HRM_v0_2.zip" -DestinationPath . -Force
cd .\ngu_personnel_crm
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m uvicorn ngu_crm.app:app --host 127.0.0.1 --port 8073
```

Открыть `http://127.0.0.1:8073/`. Для остановки нажать `Ctrl+C`. Демо-база `demo.db` создаётся в этой папке при запуске. Если архив имеет другое имя, подставьте его фактический путь. Не копируйте эти файлы в `Food_Porn` или `omnibot_crm`.

Если версия 0.1 уже установлена, сначала остановите сервер (`Ctrl+C`), сделайте копию `demo.db`, затем распакуйте 0.2 с `-Force` в родительскую папку проекта и запустите той же командой. Новые демонстрационные таблицы создаются при запуске; старые демо-записи сохраняются. Не копируйте `.venv` и `.db` из архива: их там нет.

## v0.5: доступ і картка

Екран адаптований до 1366×768 та більших ноутбуків. Власник створює ролі та користувачів у `/admin/roles`; права перегляду, редагування і видалення по розділах перевіряються на сервері. Видалення реалізоване лише для синтетичних чернеток і записів без пов'язаної історії. Картка має адміністративні поля звання/категорії, спеціальності, початку служби та примітки; POST дії фіксуються в короткому журналі. При першому запуску виконайте `python -m ngu_crm.cli create-admin --username owner`. Деталі встановлення: `UPDATE_v0_5_POWERSHELL.md`.


## v0.6: щільний робочий простір

Оновлено табличний реєстр персоналу: пошук, статус, пагінація, колонки, контекстне меню правою кнопкою, перемикач щільності. Картка показує кадрові події, штатну історію, відсутності, зайнятість та майно. Розділ «Групові дії» створює планову адміністративну зайнятість для 1–100 вибраних синтетичних карток на підставі одного зареєстрованого DEMO-наказу; запис для кожного створюється атомарно. Реєстр категорій доступу містить лише метадані демонстраційних таблиць, не відомості з офіційним грифом. У футері: Built by Bondarev E.
